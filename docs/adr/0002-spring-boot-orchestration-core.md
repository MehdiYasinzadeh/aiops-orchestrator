# 0002. انتخاب Spring Boot 3 و Java 21 برای هسته ارکستراسیون در برابر پایتون یکپارچه

* **وضعیت:** پذیرفته‌شده (Accepted)
* **تاریخ:** 2026-11-20
* **تصمیم‌گیرنده:** مهدی یاسین‌زاده
* **دامنه:** انتخاب پشته فناوری بک‌اند و هسته مدیریت پلتفرم

---

## ۱. زمینه و بیان مسئله (Context)

پلتفرم AIOps نیازمند یک هسته مرکزی است که وظایف زیر را به صورت هم‌زمان و با قابلیت اطمینان بالا انجام دهد:
1. دریافت پیوسته و با کارایی بالای استریم لاگ‌ها از سیستم‌های توزیع‌شده.
2. مدیریت بافرهای متحرک در حافظه رم بدون ریسک نشت حافظه (Memory Leaks).
3. مدیریت اتصال به پایگاه‌های داده سازمانی و انتشار متریک‌ها.
4. هماهنگی میان کلاینت‌های مختلف (سرویس پایتون، موتور LLM و دیتابیس).

پایتون زبان اصلی یادگیری ماشین است، اما اجرای سیستم‌های پایش و اینجکشن لاگ با توان پردازشی بالا در پایتون با چالش‌های قفل سراسری مفسر (GIL) و مدیریت استخرهای اتصال در مقیاس‌های سنگین مواجه است.

---

## ۲. گزینه‌های بررسی‌شده (Considered Alternatives)

* **گزینه ۱: پیاده‌سازی کل پلتفرم به صورت یکپارچه در پایتون (All-in-Python):**  
  *مزیت:* یکپارچگی زبانی با مدل‌های یادگیری ماشین.  
  *علت رد:* مدیریت حافظه و Multi-threading در پایتون برای پردازش استریم‌های فوق‌سریع لاگ نسبت به ماشین مجازی جاوا (JVM) ضعیف‌تر است و اتصال سازمانی پایداری کمتری دارد.
* **گزینه ۲: استفاده از زبان Go برای کل پلتفرم:**  
  *مزیت:* کارایی عالی و همروندی سبک.  
  *علت رد:* عدم تطابق با مهارت‌های تیم اصلی، اکوسیستم کتابخانه‌ای ضعیف‌تر در لایه هوش مصنوعی نسبت به پایتون/جاوا.
* **گزینه ۳: معماری تفکیک‌شده (Polyglot): هسته Spring Boot 3 / Java 21 + میکروسرویس پایتون برای هوش مصنوعی:**  
  سپردن وظایف زیرساختی به قوی‌ترین فریم‌ورک سازمانی دنیا و سپردن هوش مصنوعی به پایتون.

---

## ۳. تصمیم اتخاذشده (Decision)

ما **گزینه ۳** را انتخاب کردیم:
* هسته هماهنگ‌کننده، مدیریت استریم لاگ، بافرینگ، کلاینت‌های تاب‌آور (Resilience4j) و پایگاه داده در **Java 21 و Spring Boot 3.x** با بهره‌گیری از نخ‌های سبک (Virtual Threads) پیاده‌سازی می‌شود.
* کد پایتون صرفاً به اجرای مدل یادگیری ماشین در یک میکروسرویس ایزوله محدود شده و ارتباط میان این دو از طریق **gRPC پرسرعت با Protocol Buffers** برقرار می‌گردد.

---

## ۴. پیامدها و اثرات تصمیم (Consequences)

### پیامدهای مثبت:
* **پایداری سازمانی ۱۰۰٪ (Enterprise Grade):** بهره‌مندی از مدیریت حافظه JVM، بهینه‌سازی GC و مقیاس‌پذیری عظیم نخ‌های مجازی جاوا ۲۱.
* **تسلط و شفافیت کامل فنی تیم مهندسی:** کدنویسی هسته بیزنس در استانداردترین بستر سازمانی بدون وجود بخش‌های مبهم (Black Box).
* **تاب‌آوری بالا:** بهره‌گیری از ابزارهای بومی مانند Spring Data JPA و Actuator.

### چالش‌ها و هزینه‌ها:
* نیاز به بیلد و نگهداری دو محیط توسعه (JVM برای جاوا و Virtualenv برای پایتون) که با استفاده از کانتینرهای مستقل حل می‌شود.
